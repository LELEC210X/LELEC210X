\section{Non-integer data representations}

The computation of mel-vectors from raw audio samples is performed by a sequence of signal processing operations in the MCU. In embedded systems where resources are limited, we want to achieve the best tradeoff between computation accuracy and processing burden, which requires a detailed understanding of the data representation and the performed operations.

\paragraph{Floating-point} As a reminder, when you use Python or another high-level programming language to process data, you generally use \textit{floating-point} variables to represent real numbers. It is close to the scientific notation in the sense that it contains a sign, a fraction and an exponent, as illustrated in \autoref{fig:floating-point}. The value represented in the figure is $2^{-3} \times 1.25 = 0.15625$ according to \autoref{eq:floating-point}. Because of their structure, floating-points cannot be manipulated like integers. The basic operations (addition, multiplication, etc.) do not require the same bitwise manipulations as for integers.

\begin{equation}
\begin{aligned}
\text{value} = & (-1)^{\text{sign}} \times 2^{\text{exponent}-127} \times \text{fraction}\\
& \text{with sign} = b_{31}\\
& \text{exponent} = \sum_{i=0}^{7}b_{23+i}2^i\\
& \text{and fraction} = 1+\sum_{i=1}^{23}b_{23-i}2^{-i}
\label{eq:floating-point}
\end{aligned}
\end{equation}
\begin{figure}[H]
    \centering
    \includegraphics[width=.8\textwidth]{figures/floating-point.png}
    \caption{32-bit floating-point illustration.}
    \label{fig:floating-point}
\end{figure}

\begin{bclogo}[couleur = gray!20, arrondi = 0.2, logo=\bcinfo]{Floating point unit (FPU)}
Many processors are equipped with hardware accelerators dedicated to performing floating-points operations, named floating point units (FPU). Otherwise, the specific bitwise manipulations must be executed in software and require multiple CPU cycles for one basic operation. Check out our MCU's datasheet in the technical resources on Moodle to find out if it is equipped with a FPU.
\end{bclogo}

\paragraph{Fixed-point} Fixed-points represents fractional numbers by splitting the bits in $i$ integer bits and $f$ fractional bits. The first integer bit may be negative if using \textit{signed fixed-point} \texttt{qi.f} or positive if using \textit{unsigned fixed-point} \texttt{uqi.f}. \autoref{fig:fixed-point} illustrates an example of a signed fixed-point with $i = 4$ and $f = 4$. We often use \texttt{q1.f} (e.g. \texttt{q1.15}, shortened \texttt{q15}) such that the range is $[-1;1[$. Unlike floating-points, basic operations on fixed-points require the same bitwise manipulations as on integers, which makes them very efficient.

Keep in mind that the fixed-point representation is purely an interpretation of the bits significance. The CPU does not make any difference between integers and fixed-points. You can see in the code that the type \texttt{q15\_t} is just an alias for \texttt{int16\_t}.

\begin{figure}[H]
    \centering
    \includegraphics[width=.6\textwidth]{figures/fixed-point.png}
    \caption{8-bit fixed-point illustration.}
    \label{fig:fixed-point}
\end{figure}

\begin{bclogo}[couleur = gray!20, arrondi = 0.2, logo=\bcinfo]{Rescaling fixed-points}
By moving the radix point position using bit shifts, for example from a \texttt{q1.7} to a \texttt{q4.4} by applying $\gg3$, you change the representation without changing the represented value, which is called \textbf{rescaling}. It provides a tradeoff between range and resolution as you trade integer bits for fractional bits. \texttt{q1.7} has a range of $[-1;1[$ and a resolution of $2^{-7} = 0.0078125$ while \texttt{q4.4} is in $[-8;8[$ with a resolution of $2^{-4} = 0.0625$.

Rescaling fixed-points is essential when performing operations such as additions or multiplications because we want to have the best resolution possible while preventing \textbf{overflows}.
\end{bclogo}

\begin{bclogo}[couleur = gray!20, arrondi = 0.2, logo=\bcinfo]{Data races and volatile variables in C}
The main function and the interrupt handler are concurrent: they are not part of the same \textit{execution flow}.
With all concurrent programming, you have to be careful when writing to variables that are shared (concurrent reads are always ok), as the result of the execution might be non-deterministic (i.e. it depends on the exact way the execution flows are interleaved). This is called a \textbf{data race}.

For instance, if you increment a variable (which takes 3 instructions: load, add and store) both from \texttt{main()} and from an interrupt handler, you have a data race if you take no extra precaution: if the \texttt{main()} is interrupted just after the load, the variable gets incremented by only 1 instead of 2.

In order to avoid data races, all concurrent read and writes should be either \textbf{atomic} (roughly, a single load/store) or \textbf{synchronized} (through locks, etc.).

This is further complicated by the C compiler optimisations that might discard writes to a variable if it assumes it is useless (not read later in the execution flow).

As a result, whenever a variable is \textbf{shared} (accessed by multiple execution flows), or represents a \textbf{memory-mapped control register}, you have to make it \texttt{volatile}. This prevents the compiler to optimise accesses to the variable and allows their use in concurrent execution flows.

\textit{This was only a very limited introduction! To go further: \url{https://blog.regehr.org/archives/28}. You may also search the keywords: C memory model; atomic memory access ordering; memory barrier.}
\end{bclogo}

\begin{bclogo}[couleur = gray!20, arrondi = 0.2, logo=\bcinfo]{Interrupt callback good practice}
Interrupt-based programming must be designed such that \textbf{real-time constraints} are respected. There are two common techniques to prevent the processor being locked up while executing a long task.
\begin{enumerate}
    \item Delegate the long processing from an ISR to the main execution flow. A global variable is used to signal the execution state ;
    \item Configure priority between different interrupt types, such that some long-running ISR can be interrupted by other, higher-priority ones. This is managed by the NVIC, note that 0 is the highest priority.
\end{enumerate}
\end{bclogo}

\section{Continuous acquisition of feature vectors}

\subsection{Double-buffering technique}

In order to acquire audio samples continuously, we need two buffers : one is filled in by the DMA while the other one is being processed, then the other way around. This technique is called \textbf{double buffering} and is illustrated in \autoref
{fig:double-buffering}. Instead of declaring two different buffers, we will rather use one big buffer cut in halves. The DMA actually triggers interrupts not only when the the buffer is full, but also when half the buffer is full, which achieves exactly what we want. You already configured the DMA in circular mode, so nothing needs to be changed in STM32CubeMX.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{figures/double_buffering.pdf}
    \caption{The double-buffering technique.}
    \label{fig:double-buffering}
\end{figure}

Adapt the code in \texttt{acquisition.c} by following these steps :
\begin{enumerate}
    \item Replace the declaration of the global variable \texttt{samples\_single\_buf} with the declaration of a double buffer and pointers to the two halves ;
\begin{lstlisting}
// Double buffer for raw samples
static volatile uint16_t samples_double_buf[2*SAMPLES_PER_MELVEC];
// These are simply pointers to the first and middle element of double buf
static volatile uint16_t *samples_buf[2] = {&samples_double_buf[0], 
    &samples_double_buf[SAMPLES_PER_MELVEC]};
\end{lstlisting}
    \item Update the function call that starts the DMA accordingly in \texttt{acquisition\_start()};
    \item Add this callback function, common to both (half and full) DMA interrupts. Note that we no longer stop the acquisition at this point ;
\begin{lstlisting}

 * @brief Callback when one of the two buffers is ready for processing.
 * @param[in]  buf_cplt  Buffer ready index (0 or 1).
 */

{

        DEBUG_PRINT("Error : Samples buffer full (timing constraint violation)\r\n");
        Error_Handler();

    samples_buf_to_process = samples_buf[buf_cplt];
    is_processing = 1;
}
\end{lstlisting}

\end{enumerate}
